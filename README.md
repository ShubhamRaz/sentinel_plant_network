# Sentinel Plant Network

**Risk-oriented sparse sensing and irrigation decision support for potato and tomato.**

This repository contains (1) Python agronomic/control models, (2) calibrated digital-twin simulations, (3) firmware prototypes for ESP32-S3/SX1262 nodes and a local gateway, and (4) a journal manuscript draft.

> **Evidence boundary:** data generated by \`src/run_experiments.py\` are synthetic digital-twin outputs. They are not field observations. Public-dataset validation is a separate workflow and is only complete after the researcher downloads the source data, records the exact version/licence, runs the adapters, and reviews the generated reports. No water-saving, yield, or disease-reduction claim should be presented as field-validated without a physical randomized field trial.

## Protocol v2.0 hardware scope

The target design remains the INR 15,790 two-node kit described in the protocol: ESP32-S3-WROOM-1, SX1262 at 865–867 MHz, BME280, MLX90614, capacitive leaf-wetness and soil-moisture probes, 3.2 V / 6000 mAh LiFePO4 battery, 6 V / 3 W solar panel, 12 V latching valve, and YF-S201 flow meter. No camera or computer-vision hardware is included.

The firmware is an engineering prototype, not certified or field-safe production firmware. Verify the exact SX1262 module pinout (including RESET/BUSY if required), radio PA/EIRP limits, driver design, valve polarity, flow calibration, watchdog behaviour, and fail-safe hydraulic arrangement before connecting a real water line. Bench-test with a current-limited supply and a dummy load first.

## Quick start

Python 3.10–3.12 is recommended.

\`\`\`bash
python -m venv .venv
# Windows PowerShell: .venv\\Scripts\\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
\`\`\`

Run the test suite (22 automated unit tests):

\`\`\`bash
pytest -q
\`\`\`

Run reproducible synthetic digital-twin simulations:

\`\`\`bash
python src/run_experiments.py --seed 20261106 --config config.json --output-dir .
\`\`\`

The runner writes generated CSVs beneath \`data/simulated_digital_twin/\`, results beneath \`results/simulated_digital_twin/\`, and figures beneath \`figures/simulated_digital_twin/\`. Use a different \`--output-dir\` to keep generated files outside the source tree. Re-running with the same seed and dependencies should produce deterministic tabular outputs.

## Public real-dataset validation

Downloaded original files are intentionally **not committed** to Git. Place extracted files under `data/raw_public/` and retain the original dataset README, data dictionary, DOI, version, and licence.

Verified public datasets:

| Dataset | Mendeley DOI | Version | Licence | Purpose in Protocol v2.0 |
|---|---|---|---|---|
| [Tomato irrigation and weather](https://data.mendeley.com/datasets/c837v6p8ph/2) | 10.17632/c837v6p8ph.2 | V2 | CC BY 4.0 | 24h VWC forecasting & irrigation telemetry validation |
| [Seven-site leaf wetness](https://data.mendeley.com/datasets/sd4b8vpvyb/1) | 10.17632/sd4b8vpvyb.1 | V1 | CC BY-NC 4.0 | Microclimatic LWD diversity & Wallin vs. LWS-modified DSV |
| [Libelium two-node olive grove](https://data.mendeley.com/datasets/cnfh4stzzx/2) | 10.17632/cnfh4stzzx.2 | V2 | CC BY 4.0 | Two-node telemetry quality, packet gaps, and spatial decoupling |

Canonical mappings are provided in `data/mappings/`. Run the complete validation pipeline:

```bash
# 1. Tomato Multi-Sector Forecasting (Zones 1 & 2 preprocessed open-field)
python src/real_data_validation.py \
  --dataset tomato \
  --input "data/raw_public/tomato/Soil Moisture, Irrigation Actuator and Weather Dat/02_processed_data/preprocessed/dataset_zone_1_preprocessed.csv" \
          "data/raw_public/tomato/Soil Moisture, Irrigation Actuator and Weather Dat/02_processed_data/preprocessed/dataset_zone_2_preprocessed.csv" \
  --mapping data/mappings/tomato_mapping.json \
  --step-minutes 10.0 \
  --output-dir results/real_data_validation

# 2. Leaf Wetness Duration & Agrometeorology (All 7 microclimate stations)
python src/real_data_validation.py \
  --dataset leafwetness \
  --input "data/raw_public/leafwetness/Leaf Wetness and Agrometeorological Dataset/site1.csv" \
          "data/raw_public/leafwetness/Leaf Wetness and Agrometeorological Dataset/site2.csv" \
          "data/raw_public/leafwetness/Leaf Wetness and Agrometeorological Dataset/site3.csv" \
          "data/raw_public/leafwetness/Leaf Wetness and Agrometeorological Dataset/site4.csv" \
          "data/raw_public/leafwetness/Leaf Wetness and Agrometeorological Dataset/site5.csv" \
          "data/raw_public/leafwetness/Leaf Wetness and Agrometeorological Dataset/site6.csv" \
          "data/raw_public/leafwetness/Leaf Wetness and Agrometeorological Dataset/site7.csv" \
  --mapping data/mappings/leafwetness_mapping.json \
  --timezone UTC \
  --wet-threshold 20.0 \
  --night-start-hour 18 \
  --night-end-hour 6 \
  --output-dir results/real_data_validation

# 3. Libelium Two-Node Olive Grove (Goraj-1 and Goraj-2 telemetry)
python src/real_data_validation.py \
  --dataset libelium \
  --input "data/raw_public/libelium/A Libelium-Based Multisensor Dataset for Precision/extracted/Libelium_Olive_Grove_Dataset_Goraj_Kucova_Albania/Libelium_Olive_Grove_Dataset_Goraj_Kucova_Albania/libelium_measurements_quality_controlled.csv" \
  --mapping data/mappings/libelium_mapping.json \
  --output-dir results/real_data_validation

# 4. Generate Publication Figures from Real Data Validation
python src/plot_real_data_validation.py
```

Dataset documentation confirms that the Leaf Wetness dataset timestamps are reported in **UTC** (archive `README.md` and ISO8601 `"Z"` suffix). The sensor's experimentally calibrated benchmark threshold of **50.0%** is established from Filipescu, Colucci, and Trinchero (2024, *IEEE Transactions on AgriFood Electronics*, DOI: 10.1109/TAFE.2024.3401252), while **20.0%** is evaluated as a research-selected sensitivity threshold for comparative protocol analysis. Nocturnal LWD (18:00–06:00 UTC) is used for humid-pole selection, deterministically isolating Site 2 via secondary mean LWD (11.23 h/night at 20%; 9.49 h/night at 50%), while Wallin and LWS-modified DSV remain daily indices. Candidate selection is invariant across both thresholds and input order. In the hourly dataset, cadence-aware gap detection (90-minute threshold) identifies exactly 153 missing observation gaps across all 7 stations.

In the Tomato dataset, `water_vol_past_4h` is a rolling 4-hour window sum (non-cumulative); 144-step embargo purging is enforced to eliminate chronological forecast leakage. In Libelium, Protocol v2.0's $r_s < 0.70$ threshold is enforced.

Generated metrics and tables are written to `results/real_data_validation/<dataset>/`; each run records input SHA-256 values in its JSON report and updates `results/real_data_validation/DATASETS_MANIFEST.json`. High-resolution figures are saved to `figures/real_data_validation/`. These output directories are intentionally git-ignored: preserve them with your research records. The verified validation findings are detailed in [`DATA_VALIDATION_REPORT.md`](DATA_VALIDATION_REPORT.md).

## Firmware Build & Hardware Bench Testing

Firmware source is located in `firmware/`:
- `firmware/common/sentinel_protocol.h`: Shared C++17 bit-packed protocol struct (24 bytes), CRC-16-CCITT, and 6-state controller FSM.
- `firmware/node_esp32s3/node_firmware.ino`: Field node firmware for Node A (`SENTINEL_NODE_ID=1`) and Node B (`SENTINEL_NODE_ID=2`).
- `firmware/gateway_esp32s3/gateway_firmware.ino`: Edge gateway firmware managing LoRa packet ingestion, sufficiency checks, flow verification, and H-bridge latching valve control.
- `firmware/platformio.ini`: PlatformIO build configuration for ESP32-S3 targets.

Compile firmware with PlatformIO:

```bash
# Build all targets (node_a, node_b, gateway)
pio run -c firmware/platformio.ini
```

Before physical hardware deployment, execute the 7-step hardware verification plan documented in [`HARDWARE_BENCH_TEST_PLAN.md`](HARDWARE_BENCH_TEST_PLAN.md).

\`\`\`bash
latexmk -pdf -interaction=nonstopmode Sentinel_Plant_Network_Journal_Paper.tex

## Reproducibility checklist

- [ ] Record Python/package versions and the Git commit SHA.
- [ ] Record dataset DOI, version, download date, licence and checksums.
- [ ] Keep raw public files immutable; store processing scripts and mappings.
- [ ] Keep synthetic simulation outputs in the digital-twin output directory.
- [ ] Use chronological holdouts and document all resampling / missing-data handling.
- [ ] Validate firmware on bench hardware with valve disconnected before field deployment.
- [ ] Pre-register field randomization, primary endpoints, exclusion rules and statistical analysis.
